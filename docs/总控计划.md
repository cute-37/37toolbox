## 二、插件系统契约 这是所有AI的共同语言

### 2.1 核心类型定义

```typescript
// ====== 基础枚举 ======

/** 工具分类 */
type ToolCategory =
  | 'daily'        // 日常效率
  | 'image'        // 图片处理
  | 'text'         // 文本处理
  | 'dev'          // 编码开发
  | 'download'     // 下载工具
  | 'custom';      // 用户自定义

/** 工具状态 */
type ToolStatus = 'idle' | 'running' | 'success' | 'error';

// ====== 插件清单（Manifest） ======

/** 每个工具插件必须导出的清单对象 */
interface ToolManifest {
  id: string;              // 唯一 ID，kebab-case，如 'json-formatter'
  name: string;            // 显示名称，如 'JSON 格式化'
  description: string;     // 一句话描述，不超过20字
  category: ToolCategory;
  version: string;         // 语义化版本，如 '1.0.0'
  icon: string;            // Lucide icon 名称，如 'braces'
  tags: string[];          // 搜索关键词，如 ['json', 'format', 'beautify']
  hasSettings: boolean;    // 是否有设置面板
}

// ====== 工具对外暴露的渲染接口 ======

/** 工具组件接收的 Props */
interface ToolProps {
  /** 工具自身的设置（由 PluginManager 注入） */
  settings: Record<string, unknown>;
  /** 更新设置的函数 */
  onSettingsChange: (settings: Record<string, unknown>) => void;
  /** 工具状态变更回调 */
  onStatusChange: (status: ToolStatus, message?: string) => void;
  /** 全局主题 */
  theme: 'light' | 'dark';
}

/** 工具模块默认导出 */
type ToolModule = {
  manifest: ToolManifest;
  default: React.ComponentType<ToolProps>;
};

// ====== 插件加载与注册 ======

/** 插件注册表条目 */
interface PluginRegistryEntry {
  manifest: ToolManifest;
  /** 动态加载的模块（懒加载） */
  loader: () => Promise<ToolModule>;
  /** 已加载的模块缓存 */
  module?: ToolModule;
  /** 是否内置 */
  builtin: boolean;
  /** 文件路径（外部插件才有） */
  filePath?: string;
}
```

### 2.2 PluginManager API

```typescript
/** PluginManager 是对外暴露的唯一内核入口 */

interface PluginManagerAPI {
  /** 扫描并注册所有插件（内置 + 外部目录） */
  scan(): Promise<void>;

  /** 获取所有已注册的插件清单（用于侧边栏渲染） */
  getAllPlugins(): PluginRegistryEntry[];

  /** 按分类获取插件 */
  getPluginsByCategory(cat: ToolCategory): PluginRegistryEntry[];

  /** 搜索插件（匹配 name / description / tags） */
  search(query: string): PluginRegistryEntry[];

  /** 加载单个插件模块（渲染工具时调用） */
  loadPlugin(id: string): Promise<ToolModule | null>;

  /** 获取插件的设置 */
  getSettings(id: string): Record<string, unknown>;

  /** 更新插件的设置（持久化到 localStorage） */
  updateSettings(id: string, settings: Record<string, unknown>): void;

  /** 获取当前激活的工具 ID */
  getActiveToolId(): string | null;

  /** 设置当前激活的工具 */
  setActiveTool(id: string): void;
}
```

### 2.3 插件目录约定

```
# 内置插件位置
src/plugins/{tool-id}/
  ├── manifest.ts      # 导出 ToolManifest
  ├── engine.ts        # 纯逻辑函数（给 Codex）

# 外部插件位置（运行时扫描）
~/37工具箱/plugins/{tool-id}/

```

## 三、Electron 层规范（Codex 实现）

### 3.1 主进程职责（electron/main.ts）

- 创建一个 BrowserWindow（默认 1200x800，最小 900x600）
- 窗口标题 "37工具箱"
- 加载 Vite dev server（开发）或打包后的 HTML（生产）
- 注册全局快捷键 `Ctrl+Shift+K` 切换窗口显示/隐藏
- 系统托盘图标（右键菜单：显示窗口 / 退出）
- 窗口关闭时隐藏到托盘而非退出

### 3.2 IPC Channel 列表（electron/preload.ts 暴露）

| Channel | 方向 | Payload | 用途 |
|---------|------|---------|------|
| `file:read` | Renderer → Main | `{ path: string }` → `string` | 读取文本文件 |
| `file:write` | Renderer → Main | `{ path: string, content: string }` → `boolean` | 写入文件 |
| `file:openDialog` | Renderer → Main | `{ filters: FileFilter[] }` → `string \| null` | 打开文件选择框 |
| `file:saveDialog` | Renderer → Main | `{ defaultName: string, filters: FileFilter[] }` → `string \| null` | 保存文件对话框 |
| `clipboard:write` | Renderer → Main | `{ text: string }` → `void` | 写入剪贴板 |
| `clipboard:read` | Renderer → Main | `void` → `string` | 读取剪贴板 |
| `app:getVersion` | Renderer → Main | `void` → `string` | 获取应用版本 |
| `app:quit` | Renderer → Main | `void` → `void` | 退出应用 |
| `shell:openExternal` | Renderer → Main | `{ url: string }` → `void` | 在外部浏览器打开 |
| `dir:scan` | Renderer → Main | `{ dirPath: string }` → `string[]` | 枚举目录（返回目录名列表，仅返回非隐藏目录名） |

> **外部插件扫描机制**: 由于 `contextIsolation: true`，渲染进程不可直接访问文件系统。外部插件目录 `~/37工具箱/plugins/` 的扫描流程：(1) 渲染进程通过 `dir:scan` IPC 请求主进程枚举目录; (2) 主进程返回目录名列表; (3) 渲染进程 PluginManager 注册这些目录为 `builtin: false` 的外部插件; (4) 外部插件的 index.tsx 通过动态 import 加载。注意 preload 只暴露受限的目录枚举接口，不暴露通用文件读取。

## 四、设计系统（给前端 AI）

### 4.1 设计理念

37工具箱是一个给开发者/效率控用的桌面工具，应该像**浅色几何工作台**——沉稳、清透、可靠、不喧宾夺主。浅象牙/白金主题为主，浅蓝、青绿、哑金点缀。不花哨，每处设计都有功能目的。

同时，项目名中的“37”来自《重返未来：1999》的角色 37。视觉风格需要抽取她的抽象元素：白金/象牙色、浅海蓝、青绿色点缀、古希腊式几何秩序、数学/星象符号感。禁止直接使用角色立绘、头像、版权素材或将界面做成二次元痛屏；只允许通过低饱和 token、细线几何纹理、品牌标记和轻量装饰表达“37-inspired”的气质。

### 8.3 文件命名约定

- 组件文件：PascalCase（`SidebarItem.tsx`）
- 工具文件：PascalCase（`Tool.tsx`）
- 引擎文件：小写（`engine.ts`）
- 类型文件：小写（`types.ts`）
- 样式文件：小写（`globals.css`）
- 工具目录：kebab-case（`json-formatter/`）

### 8.4 接口对齐检查点

Codex 和前端 AI 在各自的 tool 目录下工作，接口对齐通过以下方式保证：

1. **manifest.ts** 由 Codex 写（它是工具元信息的源头），前端 AI 只读
2. **engine.ts** 由 Codex 写的函数签名，前端 AI 在 Tool.tsx 中 import
3. **ToolProps** 来自 `src/core/types.ts`（§2.1），两方都引用同一个类型文件
4. 如果引擎函数签名在设计阶段需要调整，必须同步更新 §6 中对应的 Spec 和 engine.ts
