## 一、概述

37工具市场让社区贡献者能创建 `.37tool` 包，用户通过市场 Tab 浏览、搜索、一键安装。整个系统分三层：包格式定义 → 验证与安装引擎 → 市场 UI。

## 二、.37tool 包格式

### 2.1 文件结构

`my-tool.37tool` 实际是一个 **ZIP 文件**（可用任意压缩工具创建），MIME type: `application/x-37tool`。

```
my-tool.37tool
├── manifest.json       # 工具清单（必选）
├── index.js            # 主模块 ES module（必选）
├── engine.js           # 引擎逻辑（可选，推荐用 index.js 内联）
├── icon.png            # 工具图标 64x64 PNG（可选，缺省用 manifest.icon）
└── assets/             # 额外资源（可选）
    ├── style.css
    └── ...
```

### 2.2 manifest.json 规范

```json
{
  "formatVersion": 1,
  "tool": {
    "id": "my-custom-tool",
    "name": "我的工具",
    "description": "自定义工具描述",
    "category": "custom",
    "version": "1.0.0",
    "icon": "zap",
    "tags": ["custom", "utility"],
    "hasSettings": false,
    "defaultSettings": {},
    "external": false
  },
  "author": {
    "name": "贡献者名称",
    "email": "",
    "url": ""
  },
  "entry": "index.js",
  "sandbox": "inherit",
  "assets": [],
  "permissions": {
    "file_read": true,
    "file_write": false,
    "clipboard": true,
    "network": false,
    "shell": false
  },
  "compatibility": {
    "toolbox_min": "0.3.0"
  }
}
```

### 2.3 字段说明

| 字段 | 必选 | 说明 |
|------|:---:|------|
| `formatVersion` | ✅ | 包格式版本，当前为 1 |
| `tool` | ✅ | `ToolManifest` 的 JSON 形式（和 types.ts 中的 ToolManifest 字段完全一致） |
| `author` | | 贡献者信息 |
| `entry` | ✅ | 入口 JS 文件名（相对于包根目录） |
| `sandbox` | | `"inherit"`（默认，用工具箱的 contextIsolation 和 IPC）、`"isolated"`（iframe，未来实现）、`"unsafe"`（无限制，需用户手动确认） |
| `assets` | | 需要注册的文件列表（用于校验完整性） |
| `permissions` | ✅ | 能力声明。工具箱渲染时严格按此切断未声明 API。用于安全提示：安装前弹窗展示权限列表，用户确认后才安装 |
| `compatibility.toolbox_min` | ✅ | 最低工具箱版本要求 |

### 2.4 permissions 详细定义

| 权限 | 默认值 | 说明 |
|------|:---:|------|
| `file_read` | false | 允许调用 `window.toolbox.file.read` 和 `openDialog` |
| `file_write` | false | 允许调用 `window.toolbox.file.write` 和 `saveDialog` |
| `clipboard` | false | 允许读写剪贴板 |
| `network` | false | 允许 fetch 外部 URL（仅浏览器 fetch，不能调 Node http） |
| `shell` | false | 允许打开外部程序和链接 |
| `database` | false | 允许使用 localStorage（默认启用的基础存储不在此列） |

### 2.5 index.js 模块规范

```javascript

// 必须同时导出 manifest 对象和一个 default React 组件

  id: 'my-custom-tool',

  description: '自定义工具描述',
  category: 'custom',
  version: '1.0.0',
  icon: 'zap',
  tags: ['custom'],
  hasSettings: false,
};

export default function MyTool({ settings, onSettingsChange, onStatusChange, theme }) {
  // React 组件...
  // 所有共享组件（Button、Input、TextArea 等）可通过以下方式获取：
  // const { Button, Input } = window.__37toolbox_shared__;
}
```

**共享组件注入**: 工具市场包在安装时会被注入一个桥接层：
```javascript
// 安装时自动包装
import originalModule from '用户提供的index.js';
window.__37toolbox_shared__ = await import('../../components/shared');
// ... 注册 originalModule 到 PluginManager
```

## 三、安装流程

### 3.1 用户视角

1. 用户打开工具箱 → 设置 → 工具市场 Tab
2. 市场展示可安装的工具列表（从远程 index.json 拉取，或用户手动浏览本地 .37tool 文件）
3. 点击某个工具 → 查看详情页（manifest 完整信息 + 作者 + 权限列表 + 截图）
4. 点击"安装" → 权限确认弹窗（列出所需权限，用户确认）
5. 安装中 → 进度条 → 安装完成 → 工具出现在侧边栏

### 3.2 系统视角

```
1. 下载/选择 .37tool 文件
2. 解压 ZIP
3. 校验 manifest.json 完整性和格式
4. 校验 permissions 字段是否合法
5. 校验 entry 文件是否存在
6. 检查 ID 是否与已有工具冲突（如冲突 → 弹出"覆盖/新建"选择）
7. 复制到 ~/37工具箱/plugins/{id}/
8. 注入权限桥接层（包裹 index.js，截断未声明 API 的 window.toolbox 调用）
9. 注册到 PluginManager
10. 写入安装记录到 localStorage（key: `37toolbox:installed`）
11. 通知侧边栏刷新
```

### 3.3 卸载流程

1. 用户右键 → 卸载（仅非内置工具）
2. PluginManager.uninstall(id)
3. 删除 `~/37工具箱/plugins/{id}/` 目录
4. 从安装记录中移除
5. 清除该工具的 localStorage 设置

## 四、校验规则

### 4.1 manifest.json 校验

```
✅ formatVersion ∈ {1}
✅ tool.id 为 kebab-case，不含空格、特殊字符
✅ tool.name 为非空字符串
✅ tool.category 为有效分类 ID
✅ tool.version 为有效语义化版本
✅ tool.icon 为非空字符串（不一定在 ToolIcon 映射中，外部工具可用自定义 SVG）
✅ tool.tags 至少 2 个元素
✅ permissions 对象存在，所有 key 为有效权限名
✅ entry 字段存在
✅ compatibility.toolbox_min ≤ 当前工具箱版本
```

### 4.2 安全校验

```
✅ entry 文件存在且为 .js / .mjs
✅ entry 文件大小 ≤ 5MB（防止包炸弹）
✅ 所有路径不含 `../` 遍历（防止 zip slip 攻击）
✅ 整个包大小 ≤ 20MB
✅ permissions 中未声明的能力在运行时被切断
```

### 4.3 校验实现

`src/core/packetValidator.ts` — 独立于 PluginManager 的纯函数，可以单测。

```typescript
export function validatePacket(json: unknown): { ok: true; data: PacketManifest } | { ok: false; errors: string[] }
```

## 五、远程市场（后续 v0.5）

### 5.1 远程 index 格式

```
https://market.37toolbox.com/index.json
```

```json
{
  "version": 1,
  "tools": [
    {
      "id": "my-tool",
      "name": "My Tool",
      "description": "Description",
      "version": "1.0.0",
      "author": "Author",
      "category": "custom",
      "download_url": "https://.../my-tool-1.0.0.37tool",
      "size_bytes": 45000,
      "sha256": "abc123...",
      "created_at": "2026-06-28T00:00:00Z",
      "min_toolbox_version": "0.3.0",
      "screenshots": ["https://.../screenshot1.png"],
      "permissions": ["clipboard"],
      "tags": ["utility"]
    }
  ]
}
```

### 5.2 搜索与排序

- 搜索: 匹配 name / description / tags（前端实时过滤，不需要额外请求）
- 排序: 按下载量 / 评分 / 更新时间
- 分页: 每页 20 个

### 5.3 部署方式（2026-06-28 已实施）

最简单的托管方式：把 `docs/market-index.json` 直接推送到 GitHub，用 raw.githubusercontent.com 的 URL 作为市场地址：

```
https://raw.githubusercontent.com/cute-37/37toolbox/main/docs/market-index.json
```

这完全免费，无需额外服务器。工具贡献者提交 PR 修改这个 JSON 文件即可。CI 可以自动验证新增条目。

### 5.4 用户自定义市场

用户可以在设置中添加多个市场 URL。目前前端代码中 `CUSTOM_MARKET_KEY`（localStorage key `37toolbox:custom-market-urls`）预留了接口，UI 尚未实现多市场切换。

## 八、类型定义（已加入 src/core/types.ts）

```typescript
/** 包格式版本 */
export const PACKET_FORMAT_VERSION = 1;

/** .37tool 包的 manifest.json 顶层结构 */
export interface PacketManifest {
  formatVersion: number;
  tool: ToolManifest;
  author?: { name?: string; email?: string; url?: string };
  entry: string;
  sandbox?: 'inherit' | 'isolated' | 'unsafe';
  assets?: string[];
  permissions: {
    file_read?: boolean;
    file_write?: boolean;
    clipboard?: boolean;
    network?: boolean;
    shell?: boolean;
    database?: boolean;
  };
  compatibility: { toolbox_min: string };
}

/** 有效的权限名列表 */
export const VALID_PERMISSIONS = ['file_read', 'file_write', 'clipboard', 'network', 'shell', 'database'] as const;
export type Permission = typeof VALID_PERMISSIONS[number];

/** 已安装工具包记录 */
export interface InstalledPackage {
  id: string;
  installPath: string;
  installDate: string;
  version: string;
  source: string;
}

/** PluginManager 市场接口 */
export interface MarketplaceAPI {
  installFromPath(path: string): Promise<{ ok: boolean; error?: string }>;
  installFromUrl(url: string): Promise<{ ok: boolean; error?: string }>;
  uninstall(id: string): Promise<boolean>;
  getInstalledPackages(): InstalledPackage[];
}
```
